# Лабораторная работа №1

## Проектирование поведения NPC с использованием конечного автомата состояний

Видео на ютубе: https://youtu.be/p38sD34XloA

Это мой небольшой 3D игровой прототип, разработанный в рамках лабораторной работы по проектированию поведения NPC с использованием конечного автомата состояний (FSM)
В проекте есть управляемый игрок и два типа противников:
- обычный противник с направленным полем зрения 180°;
- телепортирующийся противник со сканированием окружающего пространства на 360°.

Для перемещения NPC я использую Unity NavMesh, благодаря чему враги могут самостоятельно выбирать путь и обходить препятствия, и соответственно лучше патрулировать местность (их путь интересно реализован благодаря тому что они понимают локацию на которой находятся и выбирают более удобный путь доступный им и без мешающих преград

## Цель работы
Цель работы - изучить принцип работы конечного автомата состояний и применить его для создания поведения игровых NPC
В ходе работы реализованы:

- состояния NPC и переходы между ними;
- патрулирование игровой области;
- обнаружение игрока;
- преследование;
- атака;
- поиск игрока после его потери;
* проверка препятствий между NPC и игроком;
- отдельная способность телепортации для второго типа врага

## Реализация
Проект выполнен в Unity в 3D.
Основная логика обоих противников реализована в виде конечного автомата состояний. Каждый NPC в каждый момент находится только в одном состоянии, а переход в другое состояние происходит при выполнении определённого условия (в данном случае они используют схожие автоматы состояния, а "специальный враг" выделен именно отдельной способность телепортации)

Для навигации используется NavMeshAgent. Поэтому NPC не двигаются просто по прямой к заданной точке, а используют построенную NavMesh и могут обходить стены и другие препятствия.
Основные скрипты:
* PlayerMovement.cs
* NormalEnemyAI.cs
* TeleportEnemyAI.cs


## Игрок
Игрок управляется с клавиатуры и может двигаться в 8 основных направлениях:
* вверх;
* вниз;
* влево;
* вправо;
* четыре диагональных направления.
Камера закреплена за игроком и используется для вида сверху.

## Обычный противник
Обычный противник использует следующие состояния:


-Idle
-Patrol
-Chase
-Attack
-Search

### Idle
Враг находится в состоянии ожидания. В этот момент он не перемещается и проверяет, появился ли игрок в зоне обнаружения.
После окончания времени ожидания NPC возвращается к патрулированию.

### Patrol
Враг перемещается по доступной области NavMesh.
Вместо заранее заданных точек патрулирования NPC выбирает случайную доступную позицию в пределах заданного радиуса. После достижения выбранной позиции он некоторое время находится в состоянии Idle, а затем выбирает следующую.
Если игрок обнаружен, происходит переход в Chase.

### Chase
NPC начинает преследовать игрока, используя NavMeshAgent.
Положение игрока постоянно обновляется, поэтому направление движения меняется вместе с его перемещением.
Если игрок подходит достаточно близко, враг переходит в Attack.
Если игрок перестаёт быть видимым, враг переходит в Search.

### Attack
Когда игрок находится в пределах заданной дистанции, NPC прекращает движение и выполняет атаку через определённые промежутки времени.
Сейчас атака демонстрируется через сообщение в консоли и визуальную смену цвета противника.

### Search
После потери игрока NPC не возвращается к патрулированию сразу.
Сначала он направляется к последней известной позиции игрока и некоторое время остаётся в этой области, осматриваясь.
Если игрок снова обнаружен:
text
Search → Chase


Если игрок не найден:
text
Search → Patrol


### Обнаружение игрока
Поле зрения обычного противника составляет 180°.
Для обнаружения одновременно проверяются:
1. расстояние до игрока;
2. угол между направлением взгляда NPC и игроком;
3. наличие препятствия между NPC и игроком

Для проверки препятствий используется *Physics.Raycast*
Стены находятся на отдельном слое Walls, который используется системой обнаружения.
Таким образом, игрок не будет обнаружен через стену, даже если находится в пределах дальности и угла обзора.

## Конечный автомат обычного противника
Основные переходы состояний:
Idle → Patrol
Patrol → Chase
Chase → Attack
Chase → Search
Search → Chase
Search → Patrol
Attack → Chase


Условия переходов:
| Текущее состояние | Условие                      | Следующее состояние |
| Idle              | Время ожидания закончилось   | Patrol              |
| Idle              | Игрок обнаружен              | Chase               |
| Patrol            | Игрок обнаружен              | Chase               |
| Patrol            | Достигнута выбранная позиция | Idle                |
| Chase             | Игрок в радиусе атаки        | Attack              |
| Chase             | Игрок потерян                | Search              |
| Attack            | Игрок вышел из радиуса атаки | Chase               |
| Search            | Игрок обнаружен              | Chase               |
| Search            | Время поиска закончилось     | Patrol              |

## Телепортирующийся противник
Второй противник использует тот же базовый принцип FSM, но имеет дополнительное состояние:
Idle
Patrol
Chase
Attack
Search
Teleport

Главное отличие от обычного противника — способ обнаружения и возможность телепортации

### Сканирование
Телепортирующийся NPC периодически проверяет область вокруг себя на 360°.
Радиус обнаружения составляет 1 метр.
Сканирование выполняется через заданный интервал времени.
Если игрок находится в радиусе обнаружения и между ним и NPC нет препятствия, противник фиксирует игрока и переходит в Chase.

В отличие от обычного врага, направление взгляда не ограничивает обнаружение игрока, так как используется полное сканирование на 360°.

### Chase
После обнаружения игрока NPC начинает преследование через NavMesh.
Если игрок находится на расстоянии атаки, враг переходит в атаку
Если игрок потерян, происходит переход в поиск
Также во время преследования проверяется возможность телепортации.
Телепортация доступна только после окончания перезарядки и используется, когда игрок находится достаточно далеко.

### Teleport
В состоянии Teleport NPC временно прекращает движение и выполняет телепортацию в сторону игрока.
Для точки телепортации используется NavMesh. Перед перемещением проверяется, находится ли выбранная позиция на доступной области NavMesh.
Это не позволяет телепортироваться в случайную позицию внутри стены или в область, по которой NPC не может перемещаться.
После телепортации противник возвращается в состояние преследования


### Attack
Атака работает по тому же принципу, что и у обычного противника: при нахождении игрока в радиусе атаки выполняется действие с установленной задержкой между атаками.

## Навигация
Для перемещения противников используется Unity AI Navigation и NavMeshAgent.
NavMesh строится на основе проходимой области игровой сцены и учитывает физические препятствия.
Благодаря этому NPC может:
* обходить стены;
* самостоятельно выбирать путь к игроку;
* находить доступные позиции для патрулирования;
* находить допустимую позицию для телепортации.
Это также позволяет не создавать большое количество заранее заданных точек патрулирования.

NavMeshSurface используется для построения навигационной поверхности для NPC.

## Итог
В результате мною был создан небольшой 3D прототип с двумя различными типами NPC, в процессе возникли технические сложности и несколько раз приходилось переделывать проект + были проблемы с телепортирующимся врагом (он мог патрулировать зону вокруг себя, обходить стены, но просто игнорировал игрока и не использовал телепорт, однако в процессе был переписан его ИИ и всё стало работать именно так, как и было задумано по ТЗ)

Оба противника используют конечный автомат состояний с общими состояниями Idle, Patrol, Chase, Attack и Search
Обычный противник обнаруживает игрока с помощью поля зрения 180°, учитывая расстояние, угол обзора и наличие препятствий.
Телепортирующийся противник использует периодическое сканирование на 360° в радиусе 1 метра и дополнительно имеет состояние Teleport, позволяющее ему сокращать расстояние до игрока.

Перемещение обоих NPC выполняется через NavMesh, что позволяет им самостоятельно строить путь и обходить препятствия
## В процеесе я использовал следующие технологии
* Unity (движок)
* C# (язык программирования)
* Unity AI Navigation вместе с NavMesh (система обнаружения у ИИ)
